## Project State Summary
React 18 + Vite + TS frontend prototype ("DocuFy PSMS"). No backend; mock/localStorage data. Roles: customer, staff, admin.

### Works
- Auth context, role-based routing, ProtectedRoute, shared Layout (sidebar+header, notifications, SIEM alerts for admin).
- Customer: dashboard, new print request, orders, order tracking, payment, job board + apply. Job board reads from jobsStore.
- My Orders page: mobile back button moves out of the header into the page Top Action Bar (left of Print Request, same row). Layout gained `hideMobileBackButton` prop.
- My Orders mobile filters "See More/Show Less" toggle (see `See More / Show Less` block in CustomerOrders.tsx): Show More fields (Date From/To, Search, Clear) live in a grid drawer that animates `grid-template-rows` 0fr->1fr over 300ms on mobile (`sm:contents` wrappers keep the flat desktop flex-row layout), so the fields expand smoothly downward and push the button below them. Button = filled blue `#2F6FD6` when "See More" (collapsed), white with a `2px` blue border when "Show Less" (expanded). Drawer gets `-my-2` when collapsed so the double gap (Status toggle -> 0-height drawer -> button) doesn't add too much spacing.
- Job Board listings: when expanded, gap between the location/meta row and the details is fully removed — Card gains `gap-0` (base Card is `flex flex-col gap-6`), header container `pb-0`, details section `pt-0`.
- Staff/Admin dashboards with KPI cards.
- STATUS CARD COLORS (UnifiedOrders.tsx summary cards): each status card uses a selected / unselected fill pair (arbitrary Tailwind values) — Received #4A5568/#EDF2F7, In Queue #D69E2E/#FEFCBF, Printing #3182CE/#EBF8FF, Completed #38A169/#C6F6D5, On Hold #DD6B20/#FEEBC8, Released #0D9488/#CCFBF1, Canceled #718096/#E2E8F0. Selected = accent fill + white label/value + white/15 icon chip; unselected = light fill + white/60 chip with accent icon, hover border = accent. "All Orders" card keeps its blue style.
- GCASH ORDER PAYMENT GATE: online GCash orders are created with status 'Awaiting Payment' (dataStore) / 'awaitingPayment' (ordersStore) — NOT received/in-queue — so they do NOT appear in the Orders/queue list or any status KPI (getOrderStats counts only explicit statuses). They show in Payment Verification as Pending until admin/staff verifies (UnifiedPaymentVerification); verification sets status to 'Received' so the order then enters the queue. UnifiedOrders keeps `orders` state full (setOrders write-back preserves awaitingPayment) but derives a `queueOrders` memo (excludes 'awaitingPayment') used for the table, search/status filters, queue-order validation/positions, and the "All Orders" count. NewPrintRequest: GCash → 'Awaiting Payment' (down-payment no longer forks GCash orders to On Hold; full payment is verified instead); cash → 'Received', or 'On Hold' when a down payment is required. ordersStore.convertToDataStore/convertFromDataStore now round-trip `paymentMethod` so online cash orders aren't misclassified as GCash/pending. CustomerOrders + CustomerDashboard added an 'Awaiting Payment' badge (yellow) + status filter option; OrderTracking adds an "Awaiting Payment" amber alert card, cancel eligibility (Received/In Queue/On Hold/Awaiting Payment), and badge/icon handling.
- ATTENDANCE SYSTEM REMOVED (whole feature): deleted `src/app/utils/attendanceStore.ts` and `src/app/components/AttendanceWidget.tsx`. Removed the widget from both dashboards (AdminDashboard.tsx, StaffDashboard.tsx) so the "Quick Actions" card now sits at the top of each right sidebar where Attendance was (staff side keeps `lg:col-span-3 flex flex-col pt-[68px]` with the `flex-1` card; admin side `space-y-6` now has only the Quick Actions card). Removed the admin Staff detail dialog's Attendance tab (tabs now Profile/Access, `grid-cols-2`), the `attendanceLogs` type field + mock data + `attendanceLogs: []` on new staff, and the header/description text. NewPrintRequest.tsx lost its dead `availability` state and attendanceStore subscription (value was never rendered) plus the store import. No attendance references remain in src except one mock performance-note string ("Good attendance and punctuality") in Staff.tsx, which was left untouched.
- INVENTORY SYSTEM REMOVED (whole feature): deleted `src/app/utils/inventoryStore.ts`, `src/app/utils/inventoryIntegration.ts`, `src/app/components/staff/InventoryManagement.tsx`, `src/app/components/admin/Inventory.tsx`. dataStore.ts no longer has the `InventoryItem` interface, the `inventory` array, or any inventory methods (`getInventory*`, `add/update/deleteInventoryItem`, `getLowStockItems`, `getStockStatus*`, `getAvailablePaperSizes`, `getAvailableAddons`). NewPrintRequest.tsx seeds static paper sizes (a4/short/long/folio) and `[]` add-ons directly in useState (no store subscription) and dropped the "Inventory Stock Information" comment. Completed-order flow no longer deducts inventory (AdminOrders/UnifiedOrders/StaffQueueBoard show a single "Order X completed!" toast; UnifiedWalkInTransactions no longer deducts on queue entry). Removed all `/admin/inventory` + `/staff/inventory` menu items / quick actions (AdminDashboard, AdminOrders, StaffDashboard, StaffQueueBoard, PaymentVerification, StaffOrdersUnified, StaffPaymentVerificationUnified, StaffProfile, UnifiedWalkInTransactions) and the `manage_inventory` permission (Staff.tsx). AdminProfile permission list now reads "Manage shop operations and staff". notificationStore `type` union dropped 'inventory'. Zero inventory references remain in src.
- Staff Dashboard Active Orders box (StaffDashboard.tsx): removed the "Newest updates first · Live from Orders page" subtitle and the Received/In Queue/Printing/On Hold mini status pills from the card header (kept title + "View Full Queue" button and the table/footer). Removed the now-unused `getStatusIcon` helper and unused lucide imports (FileText, Printer, LogIn, LogOut).
- Jobs: localStorage-persisted via jobsStore (seeded w/ 3 defaults). Admin can add/archive/restore; shows for customers. Fixed status casing (active) + id assignment.
- Portfolio PDF/image preview: NO inline viewer at all. Both admin (JobBoardManagement.tsx) and customer (JobBoard.tsx) open portfolio files in the browser's NATIVE PDF viewer in a NEW TAB via a module-level `openBlobInNewTab(blob)` helper: `URL.createObjectURL(blob)` -> `window.open(url, "_blank", "noopener,noreferrer")` -> delayed `URL.revokeObjectURL(url)` (60s, after tab load) to avoid leaks/blank viewer; anchor-click fallback if popup blocked; external links via `<a target=_blank>` / `window.open`. Shared `src/app/components/shared/PortfolioPreview.tsx` (was the pdf.js viewer) DELETED. Customer file-view button labeled "View". Admin's redundant "View Portfolio" modal dialog (showResumeDialog) fully REMOVED — the View Portfolio / Open Link buttons only open the new tab, no modal.
- Logo .png imports: added src/vite-env.d.ts (/// vite/client) to clear TS "cannot find module" squiggles.
- KPI cards unified to admin style on desktop only (md:) for customer; mobile keeps blue compact style.
- Customer dashboard order: KPI grid on top, quick actions+recent orders below, info cards last. (Reverted a swap back to this.)
- SYSTEM-WIDE BLUE-WHITE THEME (semantic colors preserved): flattened all non-blue accents to the blue/white/gray system palette — purple → blue, orange → blue, pink/cyan → blue, and all NON-verified/check greens → blue. KEPT green ONLY for: check glyph icons (Check/CheckCircle/CheckCircle2 `text-green-*`) and positive/verified semantic states (password 'Strong' + requirements-met, 'Verified' badge, task 'completed', down-payment Verified). KEPT red (errors/Rejected/delete), amber/yellow (warnings/Pending). Brand blues: `#1D73EC` (customer primary) and `#2F6FD6` (admin primary) both retained (near-identical system blue). Applied mechanically across all admin/customer/staff components (~30 files).
- SYSTEM-WIDE POINTER CURSOR (desktop hover): Tailwind v4 defaults buttons to `cursor: default`, so added a global base rule in `src/styles/tailwind.css`: all native `button` and `role="button"` (non-disabled) show `cursor: pointer`. Shared `Card` component (`src/app/components/ui/card.tsx`) auto-adds `cursor-pointer` whenever a `<Card>` has an `onClick`. `data-cursor-default` attribute = opt-out keeps default cursor. Backdrop scrims (invisible click-to-close overlays in Layout, file-attachments) intentionally stay default cursor.
- MOBILE SIDEBAR NAV TRANSITION: the mobile nav Sheet is now a PERSISTENT sibling of the router (<code>MobileNavSheet</code> in App.tsx, rendered inside <code>MobileNavProvider</code> but OUTSIDE <code>RouterProvider</code>, given the router object via prop) so it survives route changes. It uses <code>useSyncExternalStore(router.subscribe, ...)</code> for active-link highlighting, its own per-role menu arrays (customer/staff/admin, admin reuses adminMenuItems), full Layout styling (logo, collapse button, profile dropdown/logout), and its own open state stored in <code>MobileNavContext</code>. Layout.tsx no longer renders a Sheet — its mobile hamburger toggles the context instead. On nav-item click, <code>navigateAndClose</code> calls <code>setOpen(false)</code> + <code>router.navigate(path)</code> IMMEDIATELY (no delay), so the next page mounts at once while the sheet plays its 300ms slide-out collision animation on top. Applies to all roles.
- DROPDOWN OPEN/CLOSE ANIMATIONS: custom dropdown menus in Layout.tsx (desktop sidebar profile, top-right profile, notifications, SIEM alerts) and MobileNavSheet profile use a shared `usePresence(open, 200)` hook (`src/app/components/ui/use-presence.ts`) that keeps the panel mounted for 200ms after close so exit CSS can play, pair it with tw-animate-css entrance classes (`animate-in fade-in-0 zoom-in-95 slide-in-from-(bottom|top)-2 duration-200`) and exit classes (`animate-out fade-out-0 zoom-out-95 slide-out-to-(bottom|top)-2 duration-200`, `pointer-events-none` while closing; backdrop scrims fade with `fade-out-0`). Closes mirror the opens exactly: the `-2` spacing suffix makes the exit slide the same 8px as the enter (plain `slide-out-to-top`/`-bottom` would slide 100% and look wrong).
